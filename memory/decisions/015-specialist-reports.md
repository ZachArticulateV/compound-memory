# Keep specialist scope and review context separate

## Context

The user authorized Phase 3 specialist roles for Claude and Codex.
Generic task packets contain plan decisions. A blind critic must not see
builder reasoning just to obtain shared result IDs.

## Decision

Keep the lead in the main session. Ship seven worker role entries.
Models inherit by default. Record actual host tools and evaluator when known.
Source maps stay bounded and report gaps. Static paths do not prove runtime flow.

Blind and integrity reviewers receive native bounded prompts and frozen files.
The lead validates the report, actual sent prompt, and source/copy fingerprints.
It then wraps the native report in the shared result envelope with current IDs.
Generic task packets reject these two roles. Submission is still not acceptance.

Truth findings in integrity reports need a named source outside canonical memory.
Unknown claims remain unknown. Report proposals never repair memory or advance freshness.
The lead runs deterministic checks and supplies their captured output.

Workers do not commit, change the shared ledger, or expand file ownership.
Lead-directed parallel waves can use existing host tools. Automated dispatch
is Phase 4. Queues, schedules, and context triggers remain Phase 5.

## Consequences

Role text is not a permission boundary. Host grants still need checks.
The narrow Claude CLI cases do not certify every nested-agent setup.
Codex uses explicit packets with the access limits from decision 014.
Desktop and cloud support require their own live evidence.
