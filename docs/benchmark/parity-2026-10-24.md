# Parity review: 2026-10-24

This review checks that Compound Memory can replace 48 upstream skills, so a
user who installs it needs none of them: 15 from mattpocock/skills, 11 from the
pstack plugin in cursor/plugins, and 22 from EveryInc/compound-engineering-plugin
(CE). Each upstream skill was read at its current commit, with its references
and the headers and main functions of its scripts. Its capabilities were
listed and compared with its home in this plugin, read from the skill and its
mode references. Each gap was classed as missing, weaker, or excluded, and
every missing or weaker gap was then closed. Upstream commits:
mattpocock/skills `5beb35b` (2026-10-19), cursor/plugins `9580c23`
(2026-10-23), and EveryInc/compound-engineering-plugin `ad4d21f` (2026-10-24).
Reviewed on 2026-10-24.

No new skill or mode was needed: every gap landed in an existing skill, mode
reference, or shared reference. Nine scripts were added or extended (one new,
eight extended), each with tests, for the facts that must be exact. Three
proposed scripts were not added; the sections say why.

## How to read this

- **Missing:** the upstream skill does it, and this plugin did not do it at all.
- **Weaker:** this plugin did it, but materially less. The bullet names what
  was lost and where it now lives.
- **Excluded:** deliberately not adopted, with the reason: vendor or host
  machinery, a persistent process, heavy process that would make a one-line
  fix heavier (decision 009), or a stronger mechanism already here.

Wording differences and things covered under another name are not gaps.
"Parity" means a user loses no capability by uninstalling the upstream skill;
excluded pieces are named in the verdict. A path that starts with a skill name
(`debug/SKILL.md`) is under `skills/`.

`docs/coverage.md` is the map this review backs: one row per upstream skill,
with its home. `tests/coverage.test.mjs` fails when a reviewed skill has no
adopted row there or no entry here.
